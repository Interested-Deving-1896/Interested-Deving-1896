# Accessibility

Accessible continuity documentation helps people verify, recover, and adapt
systems under varied conditions. Accessibility is therefore part of the
definition of done for OSP profile changes.

## Contribution guidance

- Use a logical heading order, descriptive links, and plain language.
- Provide text alternatives for meaningful images and diagrams.
- Do not communicate status, sync direction, or warnings through color alone.
- Explain complex mirror diagrams in adjacent text.
- Keep tables small and provide prose when a table is hard to navigate.
- Add captions or transcripts for time-based media.
- Preserve keyboard access, visible focus, sufficient contrast, and zoom or
  reflow behavior in rendered documentation.
- Avoid flashing, autoplay, and unnecessary animation.

Aim for [WCAG 2.2 Level AA](https://www.w3.org/TR/WCAG22/) where it applies.
Automated checks supplement rather than replace keyboard, screen-reader, zoom,
and human readability review.

Report a barrier using the accessibility issue form on the forge hosting the
affected copy. Include the page, environment when relevant, barrier, and
expected result without sharing private medical information.
