# Security policy

## Scope

Security reports for this profile repository may concern workflow permissions,
credential exposure, unsafe publication behavior, content injection, or a way
to compromise OSP continuity and provenance information.

A vulnerability in a hosted repository/project belongs with its declared
source maintainers. Do not assume that an OSP mirror is an active security
response endpoint.

## Reporting privately

Do not disclose sensitive details in a public issue, discussion, commit, or
merge/pull request.

Use the forge's private vulnerability-reporting facility when it is enabled.
For this GitHub copy, use [private vulnerability reporting](https://github.com/OpenOS-Project-OSP/OpenOS-Project-OSP/security/advisories/new).
If no private facility is available, use a private maintainer route listed in
the [profile README](README.md), or ask publicly for a private contact method
without including vulnerability details.

Include the affected repository/project, file or workflow, source and mirror
relationship, impact, reproduction steps, and any suggested mitigation.

## Response expectations

OSP is community maintained and cannot promise a fixed response or repair
deadline. Reports will be prioritized by demonstrated impact, exploitability,
and risk to users, publication credentials, or mirror integrity.
