# Accessibility

Accessibility is part of the definition of done for profile and documentation
changes.

## Contribution guidance

- Use a logical heading order and descriptive link text.
- Provide text alternatives for meaningful images; mark decorative images as
  decorative where the format permits.
- Do not communicate status or meaning through color alone.
- Keep tables small and provide prose when a table would be difficult to
  navigate.
- Prefer plain language, short paragraphs, and expanded forms of uncommon
  abbreviations.
- Add captions or transcripts for time-based media.
- Preserve keyboard access, visible focus, sufficient contrast, and zoom or
  reflow behavior in rendered documentation.
- Avoid flashing, autoplay, and unnecessarily animated content.

Aim for [WCAG 2.2 Level AA](https://www.w3.org/TR/WCAG22/) where it applies.
Automated checks are useful but do not replace keyboard, screen-reader, zoom,
and human readability review.

Report an accessibility barrier using the accessibility issue form. Include
the affected page, assistive technology or browser when relevant, the barrier,
and the result you expected. Do not include private medical information.
